조종기가 게임 폴더를 직접 띄우고(8131) 헤드리스 크롬으로 연다. 조종 명령은 8132로 받는다. 파이썬 서버를 따로 띄울 필요가 없다.

```bash
cd /Users/seungsoohan/Games/좀비킬
node qa/codex_play.cjs &
```
- `ready — game … · control …` 줄이 나오면 준비가 끝난 것이다(10~20초).
- 끄기: `curl -s -X POST localhost:8132/quit`

- **playwright를 못 찾는다고 나오면:** 네트워크가 되는 환경에서 아래를 실행한다.
  ```bash

  ```
  샌드박스 때문에 브라우저가 안 뜨면 그 사실을 사용자에게 알리고 멈춰라(추측으로 검수하지 말 것).

### 명령 보내기
여러 단계를 JSON 배열로 한 번에 보낸다.
- **작은따옴표(')가 든 JSON은 셸에 바로 쓰지 말고** `qa/codex_tmp/이름.json`으로 저장한 뒤 `-d @qa/codex_tmp/이름.json`으로 보낸다. 아래 3장의 긴 JSON 블록이 모두 그렇다.
```bash
cd /Users/seungsoohan/Games/좀비킬
curl -s localhost:8132/act -d '[{"start":true},{"hold":["KeyW","ShiftLeft"],"ms":1500},{"shot":"달리기"},{"state":true}]'
```

| 단계 | 뜻 |
|---|---|
| `{"start":true}` | 타이틀에서 클릭해 시작 |
| `{"hold":["KeyW"],"ms":1500}` | 키를 ms 동안 누름. 키 이름은 e.code(`KeyW`, `ShiftLeft`, `Space`, `ArrowLeft`, `Digit1`, `Escape`…) |
| `{"press":"KeyF"}` | 키 한 번 |
| `{"fire":300}` | 좌클릭을 ms 동안 누름(누르고 있으면 연사) · `{"click":true}`는 한 번 |
| `{"ads":true}` / `{"ads":false}` | 우클릭 조준 누름 / 뗌 |
| `{"wait":1000}` | 그냥 기다림 |
| `{"shot":"이름"}` | 화면을 `qa/codex_shots/`에 저장. **저장한 그림을 직접 열어 보고 판단하라** |
| `{"state":true}` | 상태 요약(시계, 사람 체력, 버스 체력, 처치, 레벨, 카드 선택 중인지, 가장 가까운 좀비 거리, 소음, 지구력, 위협도, 임무, 알림, fps, 드로우콜…) |
| `{"aim":"head"}` | 가장 가까운 좀비로 시선을 맞춤 — **조준 보조**(횟수를 밝힐 것) |
| `{"eval":"js"}` | 페이지에서 JS 실행(강제 상황용, 결과 4000자까지) |
| `{"evalToFile":"js","file":"이름.json"}` | 큰 결과를 `qa/이름.json`으로 저장 |
| `{"reload":true}` | 새로고침(봇을 돌린 뒤 직접 플레이로 돌아갈 때) |

- **턴제:** 명령을 처리하는 동안만 게임 시간이 흐르고, 응답이 오면 멈춘다. 생각하는 동안 좀비에게 맞지 않는다.
  - 대신 한 번에 너무 길게 움직이지 마라(보통 0.5~3초). 그다음 `shot` + `state`로 확인하고 다음 행동을 정하라.
- **응답:** `{ results, state, errors }`. `errors`는 그사이 새로 생긴 콘솔 오류다. 비어 있지 않으면 바로 기록한다.

## 2. 게임 알기 (조작은 타이틀 화면·HUD 안내가 우선)

## 3. 검수 순서

### A. 첫 60초 (2판)
- 타이틀 → 시작 → 배낭 → 첫 좀비 → 탑승까지, 처음 해 보는 사람처럼 한다.
- **잴 것:** 첫 처치까지 몇 초, 뭘 해야 할지 화면만 보고 알 수 있었는지, 막힌 곳.

### B. 직접 플레이 (최소 3판, 1판은 끝까지)
상황마다 스크린샷을 남기고, 아래를 직접 해 본다.
- **버스:** 운전, 폐차 들이받기, 들이받아 좀비 날리기, 매달린 좀비 쏘아 떼기
- **걷기:** 내려서 수색(G) → 쫓기는 느낌(심장박동·발소리·지구력) → 다시 탑승
- **무전 임무:** 하나는 성공시켜 본다
- **무기고(4:42):** 걸어서 털고 버스까지 도망
- **밤:** 손전등 켜고 끄기의 차이(보이는 정도 vs 들키는 정도)
- **레벨업 카드:** 고를 때 고민이 되는지(지배적인 카드가 있는지)

**판마다 적을 것:** 시간대별 한 줄 일지, 가장 재밌던 순간 · 지루하던 순간 · 억울하던 순간, 사망 이유가 화면에서 이해됐는지.

### C. 강제 상황 확인 (eval 사용 — 리포트에 밝힐 것)
- **버스 파괴 → 탈출:** `{"eval":"ZK.fort.state.hp = -999"},{"wait":500},{"shot":"버스파괴"}`. 그다음 직접 뛰어가 G로 시동까지 해 본다.
- **막판으로 빨리 감기:** 봇이 8:50까지 대신 하고, 거기서부터 네가 이어서 한다. 9:00 이후 버스 파괴 → 걸어서 착륙장(타워면 입구), 해일, 헬기를 직접 겪어 본다.
  - 아래 JSON을 `qa/codex_tmp/ff.json`으로 저장해 `curl -s -m 200 localhost:8132/act -d @qa/codex_tmp/ff.json`으로 보낸다(30~60초 걸림).
  ```json
  [{"eval":"(async () => { window.__runs = []; eval(await (await fetch('/qa/bot_harness.js', {cache: 'reload'})).text()); __startRun('숙련', 3); while (ZK.debug3.g.t < 530 && ZK.debug3.g.state === 'play') __continue(5); ZK.debug3.fast = false; for (const k in ZK.player.keys) ZK.player.keys[k] = false; return ZK.debug3.g.state + ' ' + ZK.debug3.g.t.toFixed(0); })()"}, {"shot":"8분50초"}, {"state":true}]
  ```
  - 같은 방법으로 `t < 275`면 무기고 직전이다.
  - 다 하면 `{"reload":true}`로 깨끗하게 돌아간다.

### D. 봇 플레이테스트 18판 (숫자 근거)
숙련도 3종(초보·보통·숙련) × 시드 1~6이다. 렌더 없이 빠르게 돌아 약 3~5분 걸린다. 시작 명령은 기다리지 않고 바로 돌아온다.
아래 JSON을 `qa/codex_tmp/batch.json`으로 저장해 `-d @qa/codex_tmp/batch.json`으로 보낸다.
```json
[{"reload":true},{"eval":"(async () => { window.__runs = []; eval(await (await fetch('/qa/bot_harness.js', {cache: 'reload'})).text()); const mc = new MessageChannel(), q = []; mc.port1.onmessage = () => { const f = q.shift(); f && f(); }; const y = () => new Promise(r => { q.push(r); mc.port2.postMessage(0); }); window.__batchLog = []; window.__batchDone = false; (async () => { for (const p of ['초보', '보통', '숙련']) for (let sd = 1; sd <= 6; sd++) { __startRun(p, sd); while (__runs.length <= __batchLog.length) { __continue(5); await y(); } const r = __runs[__runs.length - 1]; __batchLog.push(p + sd + ' ' + r.result + '@' + r.duration + ' ' + r.cause); } window.__batchDone = true; })(); return 'batch started'; })()"}]
```
- **진행 확인:** `{"eval":"__batchLog.join('\\n') + '\\n done ' + __batchDone"}`
- **끝나면 저장:** `{"evalToFile":"__export('좀비킬 코덱스 검수')","file":"codex_playtest_<날짜>.json"}`
- **집계:**
  ```bash
  cd /Users/seungsoohan/Games/좀비킬
  python3 /Users/seungsoohan/.claude/skills/game-review/scripts/summarize_playtest.py qa/codex_playtest_<날짜>.json
  ```
  생존율, 첫 보상, 분당 빅 모먼트, 레벨업 간격, 위기 횟수, 성장 배율이 나온다.
- **봇의 한계:** 봇은 타워(계단·옥상)를 아직 못 오를 수 있다. 사망 사유에 '헬기를 놓쳤다'가 많으면, 봇이 타워에서 막힌 것인지 막판 판을 직접 해 보고 가려라. 봇 한계라면 난이도 점수에 그대로 반영하지 말고 그렇다고 적는다.

### E. 성능
- 직접 플레이 중 가장 붐빌 때(최후의 파도·해일) `state`의 `fps`·`drawCalls`(장면 전체 한 프레임)를 3번 이상 적는다.
- **프레임 시간(채점표 9번 기준):** fps는 화면 주사율(60)에 묶여 여유를 못 보여 준다. 붐빌 때 아래로 한 프레임에 걸리는 시간을 잰다(게임이 0.5초 흐른다).
  `{"eval":"(() => { const t0 = performance.now(); ZK.debug3.tick(30, 1 / 60); return ((performance.now() - t0) / 30).toFixed(2) + ' ms/frame'; })()"}`
  - 참고: 8:55에 좀비 122마리일 때 3.9ms였다(M5 GPU).
- 오래 한 뒤 `{"eval":"performance.memory ? Math.round(performance.memory.usedJSHeapSize / 1048576) + 'MB' : 'n/a'"}`로 메모리가 계속 느는지 본다.
