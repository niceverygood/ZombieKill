## 적용 결과 (2026-11-10 오전 — 사용자 요청으로 1·2번 적용)

**바꾼 것**
- **히트스톱 예산 (`js3d/fx3d.js` `F.hitstop(s, minor)`):** 아래 '고치는 법 1'의 제안 D다.
  - `game3d.js`에서 처치가 아닌 몸통·산탄 명중과 작은 연쇄를 호출할 때 `minor`로 표시하고, 이런 명중은 멈추지 않는다.
  - 직전 멈춤이 끝난 지 0.25초 안이면 절반, 최근 1초 누적은 120ms까지다.
  - 주소 `?hitstop=old`는 예전 규칙, `?hitstop=off`는 끔이다.
- **붉은 섬광 제한 (`F.flash`):** 붉은 섬광(r 비율 0.8 이상)은 0.34초에 한 번만 → 1초에 최대 3번이다.

- **함께 고친 버그 — 정조준 때 엄지 깜빡임 (`js3d/gun3d.js`):**
  - 리볼버 엄지 상자 뒷면과 총 프레임 뒷면이 같은 깊이(z 0.05)에 있었다. 그래서 정조준으로 총을 정면에서 볼 때, 엄지가 프레임마다 프레임 앞뒤로 깜빡였다(z-fighting).

## 재미를 죽이는 것 (손맛 관점 · 우선순위순)

### 1. 히트스톱이 너무 잦아 무리 전투가 '렉'처럼 보일 수 있다
- **근거:**
  - 실제 시간의 5~10%가 멈춘다.
  - 숙련은 판마다 63~97초 동안 1초의 20% 넘게 멈췄고, 1초 최대 멈춤은 433~550ms다.
  - 10분 판이 실제로는 10분 36초~11분 22초(+6~14%) 걸린다.
  - 처치가 아닌 몸통 명중 하나만 분당 50번 멈춘다.
  - 모든 히트에 멈춤이 걸리니 머리 처치(0.1초)와 몸통 명중(0.045초)의 차이가 2배뿐이다. 큰 순간이 덜 도드라진다.
- **고치는 법 (제안 D):**
  1. 처치가 아닌 명중에서는 히트스톱을 뺀다. 히트마커·임팩트·소리로 충분하다.
     - `game3d.js` 리볼버: `ZK.fx3.hitstop(head ? 0.08 : 0.045)` → `if (head) ZK.fx3.hitstop(0.08)`
     - 산탄: `ZK.fx3.hitstop(kills ? 0.085 : 0.045)` → `if (kills) ZK.fx3.hitstop(0.085)`
     - 연쇄: `hitstop(big ? 0.06 : mid ? 0.035 : 0.02)` → `if (big || mid) …` (작은 연쇄 0.02는 뺀다)
  2. `fx3d.js`의 `F.hitstop`에 예산을 둔다. 직전 멈춤이 끝난 지 0.25초 안이면 절반, 최근 1초 누적은 120ms 상한이다. 구현은 `qa/juice_ab.js`의 `mode === 'D'` 부분 10줄을 그대로 옮기면 된다.
- **예상 효과:**
  - 숙련 실측으로 멈춤 9~10% → 3~4%, 20% 넘게 멈춘 초 0, 게임 판 길이 +14% → +5~7%다.
  - 머리 처치·폭발은 그대로 남으니 큰 순간과 평소의 대비가 커진다.
- **주의:**
  - 히트스톱 중에도 총은 실제 시간으로 쏴진다. 그래서 지금 규칙은 사실상 '시간 정지 보너스'(실제 시간의 약 7%)다.
  - D로 줄이면 무리 전투가 그만큼 빡빡해질 수 있다. 숙련 3판은 모두 승리했지만(최저 체력 19~34%), **초보·보통으로 다시 확인해야 한다.**
  - 연달아 나는 머리 처치가 절반(0.05초)으로 줄어드는 게 아쉬우면, 머리 처치와 폭발만 '절반' 규칙에서 빼고 상한만 적용한다.

### 2. 붉은 처치 섬광이 1초에 4번까지 → 광과민 기준 경계
- **근거:**
  - 숙련 13에서 몸통 처치의 붉은 테두리 섬광(210,20,20, 알파 0.26)이 1초에 4번 겹친 창이 2개 나왔다. WCAG 2.3.1 붉은 번쩍임 기준은 1초에 3번 이하다.
  - 보통·숙련의 나머지 판도 최악이 3번이라 한계선에 붙어 있다.
  - 도보에서 물릴 때 뜨는 붉은 **전체** 섬광(0.3)도 같은 위험이 있다. 여러 마리에게 연달아 물리면 넘을 수 있는데, 봇은 거의 버스 위에 있어 1회만 측정됐다.
- **고치는 법:**
  - `killJuice` 몸통 쪽 `flash(210, 20, 20, …)`를 마지막 붉은 섬광에서 0.34초가 지났을 때만 띄운다(예: `g.redFlashT`). 그러면 1초에 최대 3번이 보장된다.
  - `hurtPlayer`의 `flash(190, 0, 0, 0.3, 0.22)`에도 같은 시계를 쓴다.
  - 생략된 처치는 히트마커·확인음·임팩트로 충분하다.
- **예상 효과:** 위반 창 0이다. 화면이 붉게 깜빡이는 피로도 줄어든다.

### 3. 큰 사건의 히트스톱 순서가 일부 뒤집혀 있다
- **근거:** 드럼통·LPG 폭발이 0.07초로, 처치도 아닌 머리 명중(0.08초)보다 짧다. 연쇄(대)는 0.06초로 몸통 처치(0.065초)보다 짧다. 폭발은 흔들림·섬광·화각으로 보상하고 있지만, '멈칫' 크기는 작다.
- **고치는 법:**
  - 폭발 0.07 → 0.10, 연쇄(대) 0.06 → 0.08로 올린다.
  - 머리 명중(처치 아님) 0.08 → 0.06으로 내린다.
  - 1번의 120ms 상한 안에 들어간다.
- **예상 효과:** 순서가 머리 처치 = 폭발(0.10) > 산탄 처치(0.085) > 연쇄(대)(0.08) > 몸통 처치(0.065) > 머리 명중(0.06)이 된다.

## 이미 재밌는 것 (지킬 것)
- **조준이 공정하다.**
  - 흔들림·펀치는 화면에만 걸리고, 탄은 흔들림을 뺀 `aimQuat`으로 나간다.
  - 조준선과 실제 탄 방향의 차이는 p50 0.003°, p90 0.11°, p99 1.1°다. 머리보다 크게 어긋난 발은 1.2%뿐이다.
  - 카메라 펀치 스프링(K 220 · C 20)이 리볼버 연사 간격(0.28초) 안에 거의 0으로 돌아오기 때문이다.
- **흔들림이 절제돼 있다.**
  - 평균 0.17~0.30°이고, 1°를 넘는 시간은 2~5%뿐이다.
  - 최대는 7.3°(숙련 11, 큰 사건이 몇 개 겹친 순간)다. 롤은 최대 4.8°다.
  - 예전(리볼버 한 발 0.04°)처럼 안 보이는 수준이 아니면서, 계속 흔들리지도 않는다.
- **이벤트마다 피드백이 빠짐없다.** 위 표의 13가지 이벤트 모두 화면과 소리가 있다. 머리 처치에는 노란 테두리, HEADSHOT, 짧은 슬로모가 붙어 일반 처치와 확실히 다르다.
- **슬로모는 아껴 쓴다.** 머리 처치 슬로모는 1.4초에 한 번이고, 슬로모 시간은 실제 시간의 1~4%다.
- **비용이 거의 없다.** 렌더 p95가 약 +1.2ms이고, 피크 프레임은 약 5ms로 60fps 예산의 1/3이다.
- **끌 수 있다.** 설정 패널(⚙ 설정 → '화면 흔들림·섬광' 0~150%)이 흔들림·펀치·섬광 배수를 바꾼다. 단, **히트스톱·슬로모는 이 슬라이더로 바뀌지 않는다.**

## 사람이 직접 확인해야 하는 것

**준비:** 게임을 열고 콘솔에 한 줄을 붙여 넣으면, 왼쪽 위에 A/B 배지가 뜬다.
- **[ 키:** 히트스톱 규칙을 지금(예산, 적용됨) → 예전(명중마다 멈춤) → 끔 순서로 바꾼다.
- **] 키:** 화면 효과를 100 → 0 → 50 → 150% 순서로 바꾼다.
- 배지에는 '최근 1초 멈춤 ms'가 보인다. 200ms를 넘으면 빨간색이다.
- 새로고침하면 사라지고, 게임 코드는 그대로다.

- [ ] **무리 전투에 '렉' 느낌이 드나:** 20마리 이상에 리볼버를 연사할 때 화면이 끊기는 느낌이 드는가? [ 키로 지금(예산) ↔ 예전을 바꿔, 끊김이 줄면서 손맛은 남는지 본다.
- [ ] **지금(예산) 규칙에서 머리 처치:** 머리 처치를 연달아 할 때 '탁 멈추는' 쾌감이 약해지지 않는가?
- [ ] **리볼버 한 발:** 손목이 튀는 '탕' 느낌이 약한가, 적당한가, 과한가? (] 키로 0% ↔ 100%)
- [ ] **머리 처치 vs 몸통 처치:** 머리 처치가 확실히 더 짜릿한가? 차이를 바로 알아보는가?
- [ ] **산탄총:** 어깨를 치는 느낌이 나는가? 화각이 확 넓어지는 순간(+4°)이 어지럽지 않은가?
- [ ] **폭발:** 드럼통·LPG 폭발이 판에서 가장 큰 순간으로 느껴지는가? 머리 명중보다 덜 '멈칫'하게 느껴지는가?
- [ ] **발마다 번쩍임:** 총을 쏠 때마다 화면이 따뜻하게 번쩍이는 게(분당 70~136번) 거슬리거나 눈이 피로한가?
- [ ] **붉은 깜빡임:** 무리를 연달아 처치할 때 붉은 테두리가 깜빡이는 게 불편한가? 도보로 여러 마리에게 물릴 때는 어떤가?
- [ ] **멀미:** 10분 한 판을 마친 뒤 멀미나 눈 피로가 있는가? 0%에서는 사라지는가? 50%가 적당한가?
- [ ] **소리 덕킹:** 총성 뒤 배경음이 잠깐 줄어드는 게 '펀치'로 느껴지는가, 소리가 끊기는 느낌인가? (헤드폰)
- [ ] **처치 확인음:** 몸통 처치와 머리 처치 확인음을 귀로 구분할 수 있는가?
- [ ] **버스 정면충돌:** 덩치에 박을 때 앞으로 쏠리는 '쾅'(16cm · 흰 섬광)이 시원한가, 불쾌한가?
- [ ] **조준 어긋남:** 조준선에 맞췄는데 빗나간 느낌이 드는 순간이 있는가? 봇 측정으로는 거의 없지만(p99 1.1°), 사람이 빠르게 연사하면 더 클 수 있다.

## 측정 한계
- **표본이 작다:** 숙련도별 3판이다. 루프 L5~L7은 6판이었다. 생존율은 L6과 비슷한 범위로만 읽는다.
- **봇과 사람의 사격 속도가 다르다:**
  - 봇은 1초에 약 1.7발을 쏜다. 사람은 리볼버 최대 속도(0.28초 간격, 1초 3.6발)로 연사할 수 있다.
  - 사람은 히트스톱이 더 잦고, 조준 어긋남은 조금 더 크다. 해석적으로 0.2초 뒤 펀치 잔여는 약 0.3°다.
- **봇은 대부분 버스 위에 있다:** 도보 물림 섬광은 1회만 측정됐다.
- **섬광 밝기는 추정치다:** '알파 × 색 밝기 × (테두리면 0.6)'로 계산했고, 실제 화면 밝기 측정이 아니다. 밤 장면처럼 배경이 어두우면 실제 대비가 더 클 수 있다.
- **60Hz로 돌렸다:** 사람 화면에 가깝게 하려고 60Hz 고정 스텝을 썼다. L 루프(30Hz)와 판 결과를 1:1로 비교할 수 없다. 첫 판을 30Hz로 돌렸을 때는 멈춤 10.2%가 나왔다. 30Hz에서는 히트스톱이 프레임 단위로 부풀려진다.
- **성능 조건:** Browser pane이 숨은 상태에서 뷰포트를 1280×720으로 흉내 내고 이 Mac에서 쟀다. 저사양 노트북·고해상도에서는 다를 수 있다.
- **사람만 판단할 수 있는 것:** 소리(덕킹·확인음)와 '손에 붙는 느낌'은 봇이 판단할 수 없다. 위 체크리스트로 확인한다.
